# 压缩与端云实验

`rma compression` 对自建合成图进行最长边 {320,640,960} × JPEG quality {40,65,85} 的实际编码。
保存每张 JPEG、字节数、base64 后字节数和编码耗时；这是小样本工程检查，不是 VLM 质量对比或稳定的性能 benchmark。

```powershell
rma compression --image your-labelled-road.jpg --output artifacts/real-image-compression
```

真实实验建议：固定一组有标注图像与问题，将每种分辨率/质量送到同一模型，记录逐题答案和人工评分，再比较流量、P95 与质量。
不能用 JPEG 文件变小直接推导视觉问答质量不变，也不能用 mock 回答评价 VLM 准确率。

| 实验 | 控制条件 | 主要记录 |
|---|---|---|
| 门控 vs 每帧上传 | 同一录制流、检测器和帧率 | 上传数、字节、事件召回、最长等待 |
| 网络断开/恢复 | 固定事件集合，断网 30s | outbox 行数、attempts、成功与重复响应 |
| JPEG 参数 | 同一输入图像/问题 | 质量人工标注、传输字节、编码/模型时延 |
| 端检测+云 VLM vs 上传原图 | 同一任务定义 | 端耗时、往返时延、问答质量、峰值内存 |

队列持久化、去重和熔断可用 pytest 验证；Nano 的真实采集、视觉识别准确率与端到端吞吐仍待实机。
事件 captured_at 是描述性时间戳，分段计时使用各设备单调时钟；跨设备时钟差值不作为精确单向传输耗时。
